# Excel 处理工具 - GitHub + Netlify 部署指南

## 项目概述

这是一个纯前端的Excel数据处理工具，支持：
- ✅ **多文件上传与批量处理**：一次选择/拖入多个 .xlsx，每个文件独立处理
- ✅ **操作范围切换**：「当前文件」逐个处理 /「全部文件（批量）」一次性处理所有文件
- ✅ 上传Excel文件（本地处理，不上传服务器）
- ✅ Data100ID 匹配过滤（粘贴ID批量判定合格行，支持切换匹配列 A–E），执行后不合格行直接删除、预览中标红
- ✅ **结算比例计算**：总合格 ÷ 原始总完成行数 × 100%，执行ID过滤后自动显示
- ✅ **按目标比例反推交付量**：输入想要的交付合格占比（如 90%），自动算出该交付多少行、需从原文件恢复多少不合格行，可反复调整、可一键还原
- ✅ **各文件明细表**：批量模式下逐文件列出总完成/合格/不合格/结算比例/交付行数/交付合格占比，末尾自动汇总
- ✅ 按数量或比例随机保留/删除数据行（首行表头不计入）
- ✅ 删除F列及之后所有列（保留A-E共5列）
- ✅ **导出**：单文件直接下载；多文件打包成 ZIP（避免浏览器拦截连续下载）

> **两个比例口径别弄混：**
> - **结算比例** = 总合格 ÷ 原始总完成行数（固定分母，执行过滤后即为定值，例：74 ÷ 117 = 63.25%）
> - **目标比例** = 交付文件里的合格占比 = 合格行 ÷ 交付行数（可调，用来控制实际交付多少行）
>
> 所以目标比例的下限就是「结算比例」（一行不删、全部交付），上限是 100%（只交合格行）。想要更低的比例，只能减少合格行，属于「保留行/删除行」的范畴。

## 多文件批量处理说明

### 操作范围
上传后会出现「操作范围」切换器：

| 模式 | 行为 |
|---|---|
| 🎯 当前文件 | 所有操作只作用于列表中选中的那一个文件（点击文件行可切换） |
| 📚 全部文件（批量） | 所有操作作用于列表中**所有**文件，每个文件独立计算基数与结果 |

### 批量模式下的语义
- **ID 列表全局共享一份**，但每个文件**独立匹配**、独立计算结算比例（不同批次合格率不同，必须分开看）
- **目标比例逐文件执行**：每个交付文件自身的合格占比都达标
- **保留/删除行按各自基数**：批量输入「保留 30 行」= 每个文件各保留 30 行，不是总数 30 行
- **保留/删除互斥**：某文件已执行「保留行」后再执行「删除行」，新操作会**替换**旧操作，不会叠加删除
- **删除标记分层**：`ID过滤删除` 与 `行操作删除` 分开记录，切换匹配列只撤销前者，不会误伤后者

### 导出
- 「⬇️ 导出当前文件」：只导出当前选中的文件
- 「📦 批量导出（ZIP）」：把所有**已执行行操作**的文件打包成一个 ZIP（文件名形如 `批次A_processed.xlsx`），一次下载，无需逐个点

## 🔧 常见问题

### Q1: 部署后无法访问？
- 检查 Netlify 部署日志
- 确保文件名正确（`excel-processor.html`）
- 等待 1-2 分钟让 DNS 生效

### Q2: 如何更新网站？
- 修改本地文件
- 推送到 GitHub
- Netlify 会自动重新部署

### Q3: 需要构建步骤吗？
- 不需要！这是一个纯静态 HTML 文件
- 所有功能都在浏览器端运行

### Q4: 如何删除部署的网站？
- 登录 Netlify → 选择网站 → Site settings → Delete site

### Q5: 批量模式下 ZIP 导出没反应？
- ZIP 打包依赖 JSZip（从 CDN 加载）。若网络不通导致 JSZip 未加载，工具会自动降级为**逐个下载**
  （浏览器会询问"是否允许多文件下载"，需允许）

### Q6: 批量模式下每个文件的"未命中ID"数不一样，正常吗？
- 正常。批量模式共用一份 ID 列表，但每个文件只含属于自己批次的 ID，
  所以各文件"未命中"数不同是预期行为。该列仅供判断 ID 列表与文件的覆盖关系，不影响合格率计算
